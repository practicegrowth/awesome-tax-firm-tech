# Evaluating tax-preparation and e-file workflows

This worksheet helps a tax, CPA, accounting, bookkeeping, or tax-resolution firm evaluate a defined tax-preparation, review, return-delivery, or electronic-filing workflow. It is not tax, legal, accounting, compliance, or security advice. It does not determine whether a firm, preparer, taxpayer, return, form, or transmission meets any requirement.

## 1. Separate the firm workflow from the official filing process

Before evaluating software or changing a process, map each handoff from client intake through return preparation, review, taxpayer authorization, transmission, acknowledgement, correction or rejection handling, delivery, and retention. Assign an accountable firm owner to each handoff.

| Workflow question | Evidence to retain |
| --- | --- |
| Which return types, forms, jurisdictions, and filing methods are in scope? | Firm-approved scope and applicable current official guidance. |
| Which work is performed by the firm versus the platform? | Dated provider documentation and the firm’s handoff map. |
| Who can prepare, review, release, transmit, and correct a return? | Role matrix, access record, and approval or exception procedure. |
| How is taxpayer authorization recorded before transmission? | The firm’s documented process and the applicable current IRS requirements. |
| How are acknowledgements, rejects, and changes handled? | Named owner, evidence location, client-communication path, and escalation rule. |

Do not treat a product’s presence in this directory as proof of IRS authorization, e-file eligibility, accepted return types, tax-form coverage, filing status, security controls, or suitability. Confirm current provider documentation and official requirements for the specific workflow.

## 2. Verify the official-system boundary

The IRS describes e-file provider services as the path to the e-file application and transmission methods, and its e-file guidance describes separate provider roles and participation requirements. An e-file provider’s listing or a software demonstration is not an IRS endorsement of a product or a substitute for the firm’s own eligibility and compliance review. [IRS e-file provider services](https://www.irs.gov/tax-professionals/e-file-provider-services) · [IRS e-file for tax professionals](https://www.irs.gov/e-file-providers/e-file-for-tax-professionals)

For individual-income-tax return e-file workflows, the IRS’s current Publication 1345 addresses authorized-provider participation and says that an electronic return originator begins electronic submission after taxpayer authorization. Use the current publication and related official instructions rather than this worksheet to determine any operational requirement. [IRS Publication 1345](https://www.irs.gov/pub/irs-pdf/p1345.pdf)

## 3. Test representative work and exceptions

Use approved test scenarios that reflect actual firm work. Include a representative standard return, a complex or multi-state return if applicable, a missing-information case, a review change, a rejection or correction scenario, and a client-delivery exception. Never use unnecessary live taxpayer data in a test.

| Test area | Questions to ask |
| --- | --- |
| Data intake and import | Are source documents, imports, and manual entries traceable to the correct client and tax year? |
| Preparation and diagnostics | Can the team identify required information, warnings, assumptions, and unresolved review items? |
| Review and release | Does the workflow prevent a return from moving forward before the firm’s required review and authorization steps? |
| Transmission and acknowledgement | Can the firm identify the transmission state, acknowledgement, rejection, or next action without relying on a vague status label? |
| Corrections and amendments | Is there a documented path for ownership, review, taxpayer communication, and retained evidence? |
| Client delivery and retention | Can the client receive the approved materials through the intended channel, and can the firm retrieve its records under its policy? |

## 4. Obtain provider evidence for material capabilities

Ask each provider to identify current documentation for the exact product, tier, tax year, and workflow in scope. Preserve URLs, dates, product names, and open questions. At a minimum, evaluate documented coverage, supported filing paths, data-import behavior, reviewer roles, status or acknowledgement handling, access administration, export options, support escalation, commercial terms, and planned change windows.

Do not infer that an integration, state or federal form, authorization method, security control, filing deadline treatment, or outage procedure is supported because it appears in marketing copy or in another firm’s workflow.

## 5. Make a bounded decision

Record the workflow scope, accountable owner, products considered, primary sources, test cases, findings, unresolved risks, commercial assumptions, and one explicit decision:

- **Adopt** for the named workflow, with required controls and a review date.
- **Extend** the test only after named evidence or controls are completed.
- **Stop** when the firm cannot validate the needed workflow or control.

Revisit the decision before a new filing season, after a material provider release, when official filing requirements change, after an acknowledgement or delivery incident, or when the firm changes its supported return types or jurisdictions.

## 6. Escalate instead of guessing

Pause for appropriate professional, technical, or official guidance when a decision concerns taxpayer authorization, e-file participation or eligibility, a return’s filing requirement, due diligence, confidential taxpayer information, a security incident, a rejected or altered transmission, a professional-service claim, or a deadline. Do not use this worksheet to resolve a taxpayer matter.
